1 · What was tested

Sources of truth, in the order this repo's QA workflow requires (_shared/qa-workflow.md): the client's source video first (8:14, Test 21 Join AFP Redesign Overview.mp4), then the Figma file (figma.com/design/FYiiXMtyvUVv4qYNxHK50h, canvas "AFP21"), then the code (local_testing/Local2/variation/vB.js + vB.css), then the live VWO preview URL. The full spec extracted from the video/Figma — including 14 items the client described but never designed, and 6 open ambiguities — lives in qa-knowledge-base/afp/afp21-membership-page-redesign.md.

The feature, as specified

A full-page replacement of the "Join AFP" page. Header/nav and footer stay exactly as they are; everything between them is torn out of #site-main and rebuilt from scratch — hero, a 13-logo auto-scrolling marquee, a 4-slide testimonial carousel, 5 "why join" feature cards, 5 alternating text/image sections, a 16-row member-value comparison table, a pricing block ("Start Your AFP Membership" — the one section every CTA should point at), a pull quote, a 15-item FAQ accordion, and a closing CTA band.

The one thing the client changed his mind about, on camera

At 0:48 in the video he says the hero JOIN AFP button should mirror the site's existing join button (i.e. navigate away). At 6:12–7:13 he explicitly retracts that — "rewind what I was saying before" — and redefines the behavior: Hero JOIN AFP and the two other JOIN AFP buttons should smooth-scroll to the pricing section; only the JOIN AFP inside that pricing section should actually navigate, and it should do so by mimicking a click on the control's own button (to preserve GA's cross-domain linker param), not by hardcoding a URL. This corrected instruction is the one this QA is written against — and it is the one thing the current build gets completely backwards (BUG-01/BUG-02).

Why the full 6-project matrix couldn't run as one command. Running all 6 projects sequentially in a single Playwright invocation ran for 1.1 hours before Chrome and most of Firefox completed, then Edge, Safari, Mobile Chrome, and Mobile Safari all crashed on their very first test with worker process exited unexpectedly (code=3221225794) — Windows' STATUS_DLL_INIT_FAILED, a resource-exhaustion signature from accumulated browser processes over that long a single run, not a product defect. Splitting into one isolated command per project (matching how the initial Chrome sanity run had already succeeded) resolved this cleanly for 5 of 6 projects.
Mobile Safari — 2 checks fixed but not re-verified to completion. This project's full 44-test run was interrupted mid-way four separate times by the same class of environment instability (worker crashes, a transient page.goto: Could not connect to server, and one run that got stopped externally after only 4 tests). Across those partial runs, 42 of 44 checks were directly observed passing at some point — including, critically, the "next/prev arrows navigate the carousel" test, which failed on an earlier run due to a #vwo-debugger iframe intercepting the click, and then passed cleanly once fixed with {force: true}. That exact same fix was applied to the two remaining affected tests (BUG-04's tooltip-hover check and the FAQ accordion-click check), but neither has been re-run to a clean completion afterward — the last two attempts hit a network timeout and a worker crash before reaching them. Given the identical failure mode and identical fix already proven effective on the carousel test, high confidence both are now passing, but this is fixed-but-unconfirmed-at-scale, not proof. 3 · Defects

CRITICAL

BUG-01 No CTA smooth-scrolls — every JOIN AFP button is a hardcoded external link  confirmed live, all 6 browsers

The client's corrected instruction (6:12–7:13 in the source video — he interrupted himself specifically to redirect this behavior) was that the Hero JOIN AFP, the comparison-table-bottom JOIN AFP, and the closing CTA-band JOIN AFP should all smooth-scroll to #join (the "Start Your AFP Membership" pricing section). There is no smooth-scroll JavaScript anywhere in vB.js — no scrollIntoView, no click handler referencing #join. #join is set as the section's id and then never referenced again. All 4 "JOIN AFP" buttons on the page — hero, table-bottom, the pricing section's own, and the footer band — share the exact same hardcoded href (.../membership/benefits/join-now), confirmed via DOM inspection on every tested browser.

Fix: wire an anchor/click handler on the hero, table-bottom, and footer JOIN AFP buttons that smooth-scrolls to #join instead of navigating.

BUG-02 The one button that should navigate goes to the wrong place and drops GA's cross-domain attribution  confirmed live against the real control page

Per the client's spec, only the JOIN AFP inside "Start Your AFP Membership" should navigate, and it should mimic a click on the control's own button rather than hardcode a URL. Live-checked the real control page (no VWO preview) on 2026-08-11: 3 of its 4 "JOIN AFP" buttons resolve to pathname /eweb/DynamicPage.aspx with query params Site, WebCode, ct, _gl — the last being GA's cross-domain linker, generated fresh per session. The variation's hardcoded .../membership/benefits/join-now is neither that domain/path nor carries _gl. For a membership-conversion experiment, losing that linker breaks the exact attribution the test is designed to measure — even if the destination URL were otherwise correct.

Separately: the site's own header nav "Join" button (unrelated to this test, unchanged) happens to use that same join-now URL with target="_blank" — very likely where the developer sourced it from, applying the client's retracted first instruction ("mirror the existing join button") instead of the corrected one.

Fix: read the control anchor's live href at click time (or dispatch a click on the control element) instead of hardcoding a URL.

HIGH

BUG-03 FREE INFO SESSION does not open in a new tab  confirmed live, all 6 browsers

Client, verbatim: "Free info session… going to this page, in a new tab, please, new tab." The anchor has no target="_blank" and no rel="noopener".

Fix: add both attributes to the FREE INFO SESSION link.

BUG-04 Tooltip width is fixed at 220px, not responsive to copy length  confirmed live, 5 of 6 browsers directly; Mobile Safari fixed-but-unconfirmed

Client, verbatim: "make sure that the tooltip that appears resizes depending on how long the copy is." All 20 tooltips currently share identical placeholder text, so this hasn't surfaced visually yet — but .tooltip-content { width: 220px } is a fixed value and will clip or under-fill as soon as real, variable-length copy goes in.

Fix: replace the fixed width with a max-width plus width: max-content, or size to content with a min/max clamp.

MEDIUM

BUG-05 Logo marquee isn't built for a seamless infinite loop  confirmed live, all 6 browsers (logoCount: 13)

buildLogosHTML() renders the 13 logos once; the CSS keyframe animates translateX(0) → translateX(-50%), a pattern that only loops seamlessly if the set is duplicated (26 nodes, so the second copy lines up exactly at the -50% mark). With one set, the strip scrolls past all 13 logos, hits empty space, then snaps back to start — a visible jump every cycle instead of the "slow, continuous" effect the client asked for.

Fix: render the logo set twice in buildLogosHTML().

BUG-06 Stale duplicate CSS makes the logo placeholder shorter than its own image's max-height  confirmed live, all 6 browsers

Two separate rule blocks target .hero__logos/.logo-placeholder — an older static-row ruleset (scoped, 3 classes, higher specificity) and a newer marquee-animation ruleset (unscoped, lower specificity) that was added without removing the first. Because specificity differs per declared property rather than per rule, the computed style is an unintended merge: height: 48px wins from the older rule while the logo <img> carries max-height: 55px from the newer one — the image can be taller than its own container, and the mismatched flex/width values between the two rulesets are a genuine cross-browser rendering risk beyond just the height overflow.

Fix: delete the old static-row ruleset entirely rather than layering a new one on top.

Visually confirmed in a live Chrome pass on 2026-08-11: as the marquee animates, a sliver of the previous logo visibly peeks out at the strip's edge before the next one settles into place — the overflow this CSS conflict predicts is a real, visible glitch during the scroll, not just a theoretical mismatch.

BUG-07 FAQ item 1 opens by default; client asked for all collapsed  confirmed live, all 6 browsers

Client, verbatim: "if you could collapse them all… that would be great." buildFaqHTML() sets the open attribute when i === 0.

Fix: remove the i === 0 condition so every item starts closed.

BUG-09 Quote banner attribution renders at 16px instead of the intended 14px  found by this Playwright suite, confirmed live

.quote-banner__author (font-size: 14px) is a <p> nested inside .quote-banner__text, which also carries .quote-banner__text p { font-size: 16px }. Both selectors share the same 3 scoped classes, but the latter adds a bare element-type selector (p), giving it higher specificity (0,3,1 vs. 0,3,0) — so the 16px rule wins regardless of source order. This is the one place the client's explicit "every attribution line should be consistent — 14px, gray" rule breaks; the testimonial-card and media-card attributions elsewhere on the page are unaffected since neither has a competing generic-p rule at that specificity.

Fix: scope .quote-banner__text p to exclude .quote-banner__author (:not(.quote-banner__author)), or raise the author rule's specificity to match.

LOW / needs confirmation, not a rendering bug

BUG-08 Variation class is cre-t-119, not the expected cre-t-21  confirmed live, all 6 browsers

Every other AFP test in this repo (cre-t-8…cre-t-19) names its variation class after the test number. This is AFP21, so the class should almost certainly be cre-t-21 — cre-t-119 looks like a copy-paste leftover from unrelated boilerplate. It's internally self-consistent (every CSS selector is also scoped to cre-t-119, so nothing visually breaks), but it risks colliding with any unrelated live experiment that happens to also use that class name, and will confuse QA/reporting cross-referencing against the Trello card and VWO dashboard.

Needs client/dev confirmation of the correct VWO variation code before this ships.

ADVISORY

Swiper's remote-eval loading pattern — fetch(...).then(code => new Function(code)()) from cdnjs.cloudflare.com. Checked live: the site's CSP includes 'unsafe-eval' in script-src, and Swiper initialized correctly on every one of the 6 tested browsers (confirmed via el.swiper truthiness checks). Not a bug, but worth knowing this pattern is CSP-dependent on a site that _client-notes.md already documents as behaving inconsistently across browsers for other injection techniques (Firefox blocks addStyleTag).

No prefers-reduced-motion handling for the logo marquee animation — worth adding alongside the BUG-05 fix.

4 · Gaps between the client's verbal spec and the Figma file

14 items the client described in the video but never actually designed in Figma — each one is a real QA risk because there's no visual reference to check the build against. Full detail in qa-knowledge-base/afp/afp21-membership-page-redesign.md §6; the build's choices for each were reviewed and are reasonable defaults, but flagged here since they weren't client-specified:

  • No mobile design in Figma at all (only a desktop frame exists) — the build's mobile breakpoints (hero title 32px/26px, subtitle 16px/15px, stacked content blocks, card-style comparison table) are the developer's own choices, confirmed working correctly across both mobile projects, but have no Figma spec to check against.
  • No tablet design or instruction at all — out of scope for this round per the user's explicit instruction ("all browsers mobile desktop"); flagged for a future pass.
  • Logo marquee, tooltip content/resize behavior, FAQ accordion icon, mobile carousel peek-treatment, hover/focus states, and the comparison table's mobile stacking pattern were all undesigned in Figma — see the knowledge-base doc for the full list and how the build resolved each.
