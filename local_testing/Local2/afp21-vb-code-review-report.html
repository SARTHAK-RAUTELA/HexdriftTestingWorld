High

CR-01 — No re-injection guard / one-time-init flag anywhere in init()

Checklist #2 and #4

init() unconditionally rebuilds #site-main and re-wires everything below it, with no check for "has this already run" and no window flag guarding it:

// vB.js:656-679
function init() {
  document.body.classList.add(variation_name);
  var mountEl = document.querySelector(MOUNT_SELECTOR);
  if (!mountEl) return;
  var controlJoinAnchor = findControlJoinAnchor(mountEl);
  mountEl.innerHTML = buildPageHTML();          // <-- no existence check first
  wireStartMembershipJoinButton(controlJoinAnchor);
  wireSmoothScrollLinks(mountEl);
  injectSwiperCSS();
  injectScripts().then(() => { initSwiper(); })

Why it matters: if this script executes twice on the same page load (SPA-style re-injection by the test platform, a duplicated script tag, back/forward-cache restore), the whole section is torn down and rebuilt from scratch: a second Swiper instance gets created on the same .testimonials-swiper selector without the first ever being .destroy()'d (its DOM was just replaced out from under it — ties into CR-06), the Swiper bundle gets re-fetched and re-evaluated (CR-02/CR-05), and every listener gets re-attached on top of the old ones. Standard fix: if (window.__creT21Inited) return; window.__creT21Inited = true; as the first line of init(), wrapping all the wiring calls.

Medium

CR-02 — injectScripts() doesn't check if Swiper is already loaded

Checklist #2 — check before injecting (specific case)

injectSwiperCSS() (vB.js:41-52) correctly guards with if (document.querySelector("#cre-swiper-css")) return; before injecting the stylesheet link — but injectScripts() (vB.js:28-40) has no equivalent guard before fetching and re-executing the JS bundle:

// vB.js:28-40
const injectScripts = () => {
  return fetch("https://cdnjs.cloudflare.com/ajax/libs/Swiper/8.3.2/swiper-bundle.min.js")
    .then((res) => res.text())
    .then((code) => {
      new Function(code)();               // <-- runs even if window.Swiper already exists
      if (typeof window.Swiper !== "function") {
        throw new Error("Swiper failed to initialize");
      }
    });
};

Fix: if (typeof window.Swiper === "function") return Promise.resolve(); as the first line.

High

CR-03 — No fallback / no .catch() if the Swiper CDN fetch fails

Checklist #5 — fallback when the code doesn't work properly
// vB.js:671-676
injectSwiperCSS();
injectScripts()
  .then(() => {
    initSwiper();
  })
  // <-- no .catch()

Why it matters: if the fetch to cdnjs.cloudflare.com/.../swiper-bundle.min.js fails (ad-blocker, corporate CSP, network blip, CDN outage), the rejection is swallowed silently — it's inside an async .then() chain, so the outer synchronous try/catch around the whole IIFE (vB.js:683) never sees it. Result: initSwiper() never runs, and the 4 testimonial slides (.swiper-wrapper children) render as an unstyled full-width block stack with dead nav buttons and no pagination dots — and there's no CSS fallback layout in vB.css for a no-JS-carousel state to make that stack look intentional. This is the one real "hidden/broken element with no fallback" case in the file.

CR-04 — Resize handler is not debounced

Checklist #6 — observer/scroll detector should debounce
// vB.js:602-608
function refresh() {
  swiperInstance.update();
}
window.addEventListener("load", refresh);
window.addEventListener("resize", refresh);
setTimeout(refresh, 300);
setTimeout(refresh, 1000);

There is no custom scroll listener left in the file (that was the old tooltip's positionTooltip() call, now removed) — so this is downgraded from the prior report's Medium to Low. The one remaining gap is resize calling swiperInstance.update() directly on every fired event with no debounce/throttle. update() is comparatively cheap, so impact is minor, but it still doesn't satisfy the rule as written.

Medium

CR-05 — Swiper bundle re-fetched every page load, never session-cached

Checklist #9 — cache fetched URLs in session storage

Same injectScripts() block as CR-02 (vB.js:28-40): every pageview of the AFP membership page triggers a fresh fetch + eval of the ~150KB Swiper bundle, with no explicit sessionStorage cache — browser HTTP cache may absorb some repeat requests but isn't guaranteed (cache-control headers on the CDN, private/incognito sessions, etc.). See CR-08 below for the recommended fix direction.

Low

CR-06 — Swiper's internal MutationObserver is never disconnected

Checklist #7 — observers disconnected after some condition
// vB.js:585-590
var swiperInstance = new Swiper(".testimonials-swiper", {
  ...
  observer: true,
  observeParents: true,
  ...

observer: true / observeParents: true makes Swiper spin up its own MutationObserver internally, which is never torn down via swiperInstance.destroy(). Low priority on a single normal page load — this section isn't expected to be removed within the page's lifetime — but becomes a real leak in the CR-01 double-init scenario, since the old Swiper instance (and its observer) never gets destroyed before its DOM is replaced.

Medium

CR-07 — wireSmoothScrollLinks() binds a listener per element instead of delegating on a live parent

Checklist #4 — event handlers should use the "live" function
// vB.js:624-637
function wireSmoothScrollLinks(scopeEl) {
  if (!scopeEl) return;
  var links = scopeEl.querySelectorAll('a[href^="#"]');
  for (var i = 0; i < links.length; i++) {
    links[i].addEventListener("click", function (e) { ... });
  }
}

This attaches a fresh closure to each matched anchor at build time rather than delegating a single click listener on mountEl (or document) and matching e.target.closest('a[href^="#"]') inside it. Functionally fine today because the anchors never change after buildPageHTML() runs once, but it doesn't follow the "live/delegated binding" pattern the checklist asks for, and it's the reason a second init() run (CR-01) would double up listeners instead of just re-matching against one persistent delegate.

Low

CR-08 — Root cause behind CR-02/CR-05: bundle is loaded via fetch + new Function() eval instead of a standard <script> tag

Independent finding — informs the CR-05 fix
// vB.js:28-34
const injectScripts = () => {
  return fetch("https://cdnjs.cloudflare.com/ajax/libs/Swiper/8.3.2/swiper-bundle.min.js")
    .then((res) => res.text())
    .then((code) => {
      new Function(code)();

Injecting a normal <script src="...swiper-bundle.min.js"> element (mirroring the existing injectSwiperCSS() pattern for the stylesheet) would let the browser's own HTTP cache handle repeat-load efficiency for free, remove the need for manual sessionStorage plumbing in CR-05, avoid the new Function()-style eval of third-party code (no Subresource Integrity hash currently pinned on this fetch either), and give a natural, checkable existence guard (if (document.querySelector('script[src*="swiper-bundle"]')) return;) for CR-02. Recommend switching the loading mechanism rather than only bolting a session-cache onto the current fetch+eval approach.

CR-09 — Redundant overlapping Swiper "refresh" triggers; inert debug flag

Checklist #8 — remove unnecessary functions/code

No genuinely dead functions in the file — every builder/wiring function is reachable from init(). Two minor cleanup items:

  • refresh() is wired to load, resize, setTimeout(..., 300) and setTimeout(..., 1000) (vB.js:605-608) — four separate triggers to call .update() once right after the instance is created. This looks like leftover defensive scaffolding; one or two of these are likely enough.
  • var debug = 0; (vB.js:4) is hardcoded off and only gates a console.log in the outermost catch (vB.js:684) — harmless, but inert in production.
