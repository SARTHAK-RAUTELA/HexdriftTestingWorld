Bugs

BUG-01 · Critical The test does not run on the booking page, which has the time selector

The brief says the test should run sitewide wherever the time selector is present. Of the 28 internal pages scanned, two have it: the homepage and the booking page /rent-a-car-in-iceland, where the homepage "Search Now" button leads. On the booking page, Convert runs three other experiences (100052722, 100052833, 100052946) but not 100052922. The page loads normally, but the test never runs there.

  • A V2 visitor picks "Noon" on the homepage, taps Search Now, and the booking page says "11 Oct 2026 12:00 PM – 13 Oct 2026 12:00 PM". This is TC06 on all 4 browsers.
  • Loading the booking page directly shows the time fields as 12:00 PM in V2, and the V1 dropdown is not centered. This is TC05 on all 4 browsers, all arms.
  • Even with targeting fixed, the booking page's "Rental time" summary is a plain <p> line. The V2 code only renames text inside button span, so that summary would still say 12:00 PM. The summary needs handling in the code too.

Fix: add /rent-a-car-in-iceland (and any other booking URLs) to the experience's URL targeting, and extend V2 to relabel the summary text.

BUG-02 · High Visitors see the original time for about 4–5 seconds before the change appears

Convert is not installed in the page <head>. Google Tag Manager injects it after the page has finished loading. Trace (Chrome desktop): page ready 2.2s → load event 3.2s → GTM requests Convert 4.7s → V2 applied 7.0s. Measured time between the time field appearing and the change applying:

  • V2: "12:00 PM" visibly flips to "Noon".
  • V1: anyone who opens the dropdown during that window gets control behavior (the list opens at 12:00 AM).
  • This is a site install issue rather than a variation-code bug, and it affects every Convert test on this site. Timings are from automated browsers. Real devices on fast networks may be quicker, but the order of events stays the same.

Fix: install the Convert snippet directly in the page <head> (synchronously) instead of through GTM. Or, at a minimum, hide the time fields until Convert has run.

BUG-03 · Medium, needs a client decision V2 also renames 12:00 AM to "Midnight"

The brief only says to change 12:00 PM to "Noon". va3.js also maps '12:00 AM': 'Midnight', so the first option in the list reads "Midnight Self Service" in V2 on all 4 browsers (TC02/TC03). If the client didn't ask for this, remove the 12:00 AM entry from LABELS. If they want it, update the brief.

BUG-04 · Low Desktop Chrome: V2 opens with "Noon" one row below center

On Chrome desktop, Noon lands 34px below center (one row is 32px), with the list scrolled 554px instead of 588px. That's still visible, but not centered like V1. On Safari desktop it was 0–8px, and on both phones 0px. Likely cause: V2 measures positions on the first animation frame while the popover's open animation is still scaling the list, whereas V1 waits about 100ms.

What passed

  • Bucketing: each preview link put the visitor in the correct variation on all 4 browsers (TC01).
  • Pick-up and drop-off fields show the right default in every arm, including inside the mobile booking sheet (TC01).
  • V1 centers 12:00 PM in both dropdowns on every browser (TC02/TC03).
  • Still 45 time options, in the same order as control. The page itself doesn't jump when the list opens.
  • Choosing 3:00 PM, reopening, and choosing the default again works in every arm. The dropdown follows the new selection and V2 shows "Noon" again when Noon is re-selected (TC04).
  • No JavaScript errors from the test code in any run.

Other notes

  • Pages scanned: 28 internal pages linked from the homepage. Only the homepage and /rent-a-car-in-iceland have a time selector.
  • Mobile: the homepage shows no times on phones. Tapping "Pick-up at" opens a full-screen sheet where the time fields live. The test applies there correctly.
  • Desktop CTA copy: in several loads the homepage button read "Check the fleet" instead of "Search Now". This is probably another live test, not Test 22.
  • Safari native error: WebKit throws a cross-origin error from the Prismic preview frame on every page, including control. It isn't caused by this test and was excluded from the error checks.
  • Local code: va3.css is leftover CSS from WIN272 (unrelated selectors, no effect). vB.js (V1) and va3.js (V2) match what the preview links deliver.
  • Edge case not covered: choosing today as the pick-up date, where earlier times may be disabled and the default may move off 12:00 PM.

How it was tested

  • Playwright on Chromium and WebKit (Safari's engine), at 1280×720 desktop and Pixel 5 / iPhone 12 emulation, one arm and browser at a time.
  • Spec: my-playwright-project/testing/lotus22-noon-default.spec.js (7 checks × 3 arms × 4 browsers = 84). Raw results: local_testing/Local2/lotus22-results/*.json.
  • The cookie banner was hidden with CSS, so no consent choice was made in either direction.
