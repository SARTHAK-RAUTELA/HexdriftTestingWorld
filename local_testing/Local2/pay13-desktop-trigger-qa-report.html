PAY13 — pay.com.au Modal: Desktop-Only + Trigger Update

QA report — 2026-09-07

Client Request

  • Convert PAY13 to a desktop-only test
  • Variation trigger: fires at 40 seconds cumulative on-site time (persists across page views within the same session), or on exit intent — whichever comes first
  • Control: stays as the PAY08 variation content, trigger changed to exit intent only

Findings Before Testing (fixed)

Gap found: vB.js (variation) and v2.js (control) both called showModal() unconditionally on page load — no 40s timer, no exit-intent listener existed anywhere in the code. Only the desktop-only audience targeting had actually been configured (confirmed via the Optimizely "Desktop Users" + "CRE_qa" audience screenshot) — the trigger-logic change had not yet been implemented.
Gap found: v2.css (control's CSS) still contained unrelated leftover WIN257 cart-modal styling — none of the .cre-t-13-* modal styles existed for the cre-t-13-control body class, so the control modal would have rendered completely unstyled.
Both fixed as part of this pass:
  • vB.js — added a trigger that races a 40s timer (start time persisted in sessionStorage so it survives page reloads/navigations) against an exit-intent (mouseout, clientY ≤ 10, no relatedTarget) listener; whichever fires first shows the modal and cancels the other.
  • v2.js — trigger simplified to exit-intent only, matching PAY08's proven mechanism, no timer.
  • v2.css — rebuilt from vB.css's modal styling, retargeted to the .cre-t-13-control body class so the control modal renders identically to the variation, just with control copy.
Not testable from these files: desktop-only targeting is enforced server-side by the Optimizely audience configuration (already set, per the screenshot supplied), not by any device check in vB.js/v2.js — so it isn't exercised by this test suite.

Test Method

Tested against a local static HTML fixture (not the live site) with Playwright's Clock API for deterministic control of the 40s timer, and synthetic mouseout dispatch for exit intent. This mirrors the approach already documented as necessary for this exact modal pattern in qa-knowledge-base/pay-com-au/cre-t-08-vB-exit-intent-mobile-timer.md — testing exit-intent/timer behavior against the live production page (which loads 15+ third-party scripts) was previously found to be flaky for timing-sensitive assertions.

Note: this local testing validates the vB.js/vB.css/v2.js/v2.css logic itself. The Optimizely campaign's live Variation/Control JS+CSS fields still need to be updated with this code before the preview links will reflect the new trigger behavior — that wasn't done as part of this pass (editing a live A/B test campaign directly wasn't assumed to be in scope without confirmation).
