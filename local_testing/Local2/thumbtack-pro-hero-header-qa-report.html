Pre-existing Site Quirks (not vB.js bugs)

The variation's core behavior — swapping the desktop hero H1 copy while leaving subhead/CTA untouched — was confirmed working correctly on every single browser tested (Chrome, Firefox, Edge, Safari Desktop, Mobile Chrome, Mobile Safari). The one real functional gap found (BUG-01) is that Thumbtack's /pro hero is actually two separate <h1> elements (a desktop one and a differently-worded mobile-only one), and the variation JS's selector can only ever reach the desktop one. Scattered secondary test failures during cross-browser runs traced back to two pre-existing Thumbtack production quirks (an AWS WAF bot-challenge on first load, and a live React hydration-mismatch error) — confirmed unrelated to this variation by reproducing them with zero variation script injected. See Site Quirks for full detail.

Code Review Findings

🔴 BUG-01 [HIGH] — mobile-only hero H1 never reached

HERO_H1_SELECTOR = '[class*="hero_heroInnerOffsetRight"] [class*="hero_heroTitle"]' can only ever match the desktop hero element. Thumbtack's /pro hero actually renders a second, separate <h1> (hero_heroInnerOffsetLeft, classes m_dn) with different baseline copy ("Get jobs in [City]." vs. "Grow your business in [City]."). The variation never touches this element on any viewport. Device targeting for this test is dWeb + mWeb, so this is a real scope gap — see the Bugs section for the practical-impact nuance.

🟡 BUG-02 [LOW, cosmetic] — double trailing space

NEW_FIRST_LINE = 'Find more customers in  ' has two trailing spaces vs. the original's one. Confirmed via innerText that browsers collapse the whitespace visually — not a visible bug, but worth a one-character cleanup.

✅ What's solid

  • Debounced re-apply-on-interval (survives React re-renders wiping the DOM edit)
  • parts[0] !== NEW_FIRST_LINE guard prevents redundant/looping writes
  • 10s failsafe timeout on both intervals
  • try/catch with debug gate, consistent with other production variations (CRE-T-136, CRE-T-09)
  • City (2nd line, geo-IP personalized) correctly left untouched by the split/rejoin logic

ℹ️ Note — vB.css in the working tree is unrelated/stale

At review time it contained leftover CRE-T-09 (pay.com.au navbar) CSS, not anything for this test. vB.js doesn't reference any of its classes — flagged so it doesn't ship by mistake alongside this test.

Site Quirks Encountered (not vB.js bugs)

  • AWS WAF Bot Control challenge on first load: thumbtack.com returns HTTP 202 with header x-amzn-waf-action: challenge on the very first navigation. The real Next.js page only hydrates ~2-5s later. A fixed short wait after page.goto() isn't reliable — gotoAndWaitPastWafChallenge() in the spec waits for a real content selector instead. Several early test failures (control text reading null) traced directly to this before the fix was applied.
  • Pre-existing React hydration mismatch (React error #418) on /pro: confirmed reproducible on Firefox with zero variation script injected — a live Thumbtack production issue, unrelated to this variation. TC-08 correctly catches it as an uncaught page error on Firefox, Safari, and Mobile Safari; this is expected and not a regression.
  • Long sequential 70+ test single-invocation runs risk worker crashes (worker process exited unexpectedly) on Mobile Chrome/Mobile Safari — observed once in a combined 72-test run, but not reproducible re-running those two projects in isolation (12/12 and 8/12 clean respectively). Resource contention from the long run, not a real defect.
  • CTA selector scoping: themed_themedButton/themed_flexWrapper classes are reused sitewide; an early, loosely-scoped CTA selector transiently matched an unrelated button reading "Next" during hydration. Fixed by scoping tightly to the hero search-box container.
