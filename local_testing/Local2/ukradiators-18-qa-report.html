1 · What was tested

Sources of truth, in the order the QA workflow requires (_shared/qa-workflow.md): the Figma spec first, then the code (local_testing/Local2/variation/vB.js + vB.css), then the live Convert.com preview. Assertions encode the design, so a failing case is a bug in the code, not a broken test.

Hypothesis

Reduce choice / narrow the path to checkout for paid-traffic landers by hiding the yellow summer-sale banner and all header nav (category links, Trade Account, Sale CTA, and the desktop search/phone/account/cart icon cluster), leaving only the logo.

Changes under test

  1. Summer-sale banner hidden (display:none)
  2. Category link / Trade Account / Sale nav items hidden (visibility:hidden)
  3. Desktop search/phone/account/cart icon cluster hidden
  4. Body top padding collapses to 0, closing the gap left by the removed banner
  5. CSS-only variation — no new DOM elements injected
Desktop matches Figma cleanly. Banner and nav text hidden, desktop icon cluster hidden, only the logo remains — verified live on the Convert.com preview across Chrome, Firefox, Safari, and Edge.

3 · Defects

MEDIUM

BUG-01 Mobile hamburger + cart icons not hidden per Figma  TC-10 reproduced on all 4 desktop browsers via mobile viewport emulation

Figma's mobile variation shows only the logo — no hamburger menu icon, no cart icon. The deployed vB.css has a selector for the desktop-style nav item text (.nav-draw-level-one > div > span) but nothing covering the mobile hamburger (.open-nav) or mobile cart icon (img[alt="cart"]) containers, which live in a different part of the header markup. Both remain fully visible to mobile visitors.

Needs a CSS selector added for the mobile hamburger/cart container before this ships to mobile traffic as currently coded.

5 · Recommendations

  1. Fix BUG-01 before launch to mobile traffic — add a CSS selector hiding the mobile hamburger (.open-nav) and cart icon (img[alt="cart"]) containers to match the Figma-specified logo-only mobile header.
  2. Re-run TC-10 across all 4 browsers after the fix to confirm 16/16 clean before sign-off.
  3. If cross-browser QA on this domain is repeated, space browser runs out (don't run the full matrix back-to-back with no delay) — ukradiators.com's Cloudflare-style bot-protection challenge can false-fail an entire browser's run otherwise. See qa-knowledge-base/ukradiators/_client-notes.md.
