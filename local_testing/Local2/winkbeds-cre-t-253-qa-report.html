WinkBeds — cre-t-253 (Buy Box Sub-total Line)

Site: winkbeds.com/pages/shop-winkbed · Platform: Convert.com · Variation files: local_testing/Local2/variation/vB.js, vB.css · Tested: 2026-07-21

What this test does

Adds a "Your sub-total is $X" line directly above the Add to Cart button in the mattress Buy Box. The total sums: mattress price (.price-row__pay-option-price / .cre-t-202-box-main-price), the Mattress Setup/Removal service price (.order-form__loadup-button-price, only counted when its class does not contain optional), and any checked accessory add-ons (input.add-to-accessory-cart). Re-renders on a 300ms interval so it stays in sync as the shopper changes selections.

Environment note — Playwright automation required a workaround on this site

Playwright automation (headless and headed) initially couldn't render the Buy Box (#orderForm) on this page — navigator.webdriver reads true under Playwright/CDP, and the page withholds the Buy Box for detected automation. Fixed by overriding navigator.webdriver to false via page.addInitScript() (first-party QA of our own variation script, not third-party evasion). Two more site quirks needed handling once the Buy Box was reachable: an intermittent "try before you buy" retention overlay and a third coexisting CRO test's timed modal can both intercept pointer events on Buy Box buttons — worked around with raw DOM .click() calls, which bypass Playwright's occlusion checks. With those in place, the full 6-browser Playwright matrix ran successfully.

Overall verdict

PASS — the sub-total line renders correctly, positions correctly, styles correctly, and its running total math is correct in every state we could exercise through the badge it reads. One pre-existing site display bug (BUG-01) was found in an edge case combo and should be flagged to the client/dev — it is not something vB.js can fix on its own since it deliberately delegates to the site's own displayed removal price rather than reimplementing WinkBeds' own pricing logic.
