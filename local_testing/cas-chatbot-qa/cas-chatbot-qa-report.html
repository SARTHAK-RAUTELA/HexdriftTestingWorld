Verdict

The page-based reference message works, with one behaviour gap and three visible text bugs. Every one of the 38 URLs tested gets its own message and 3 questions, and the message changes as the visitor moves between pages in all three browsers. But once the visitor closes the message or opens the chat, no later page shows one (BUG-01). Two cached messages show escape characters to visitors (BUG-02, BUG-03), and the message covers the mobile hero as soon as the page loads (BUG-04).

How the reference message works

  1. Visitor loads a page. The widget sends the page path and title to /agent/v1/context/suggestions.
  2. The service returns a short message and up to 3 questions for that page, cached per path.
  3. The message appears next to the launcher (live delay: 0 s). Clicking a question opens the chat and sends it.
  4. If the visitor closes the message or opens the chat, a tab-level flag stops the message on later pages, because "teaser on every page" is off.

If the service fails, takes longer than 6 s, or returns 429, the widget shows the Studio fallback "Ask me anything" with the default questions. The service allows 20 requests per minute from one IP address.

Page-to-page journey (Chromium desktop)

Fresh visitor, nothing dismissed. Each page shows a different message written for that page. Click any screenshot to enlarge it.

Bugs

BUG-01HighOpenPriority P1 · Tests W-011, W-012, W-038

Page-specific reference message stops on every later page once the teaser is dismissed or the chat is opened

Steps
On any page dismiss the teaser (X) or open the chat → navigate to another page. No teaser appears and no /context/suggestions request is sent for the rest of the tab session.
Expected
Each new page shows its own reference message (the core requirement)
Actual
No message on any later page. Cause: live config teaserEveryPage=false; dismissal/open writes sessionStorage "cas-webchat-teaser-dismissed"=1 which suppresses the teaser for the tab
Environment
Staging · Chromium/Firefox/WebKit · desktop+mobile
Suggested fix
Product decision: if per-page messages are required after interaction, enable "teaser on every page" in Studio (or re-show on page change unless the visitor explicitly closed it)
