AFP26 — Homepage Updated Design — QA Report

Client: AFP (Association for Financial Professionals) · Site: www.financialprofessionals.org
Tested: VWO preview links (Control v1 / Variation v2) · Browsers: Chrome Desktop, Safari Desktop, Mobile Chrome (Pixel 5), Mobile Safari (iPhone 12) — per this round's request
Reference: Figma side-by-side comparison image + client walkthrough video (video contained no additional visual info beyond the static Figma image — see afp26-homepage-updated-design.md for the full spec)
Result: Variation is a strong, largely faithful build of the Figma design. 3 real bugs found and FIXED in `vB.js`/`vB.css`, verified live by injecting the fixed code onto the control page across Chrome, Safari, and Mobile Chrome. One originally-reported issue (BUG-02) turned out to be a false positive from the QA tooling itself, not a code defect — corrected below.
Update (fix pass): after the client supplied the video transcript, 3 real issues were found (button-destination/font-size/weight consistency, none visible in the static Figma image alone) and have now been fixed directly in the code at local_testing/Local2/variation/vB.js / vB.css, then re-verified by injecting the updated files onto the live control page. All fixes confirmed working in Chrome Desktop, Safari Desktop, and Mobile Chrome.

Confirmed Bugs

BUG-01 [High] — 3-card promo row buttons are not level; Figma has them (nearly) aligned — FIXED & VERIFIED

Fix applied: CSS align-items:stretch alone wasn't reliably equalizing card heights on this site's markup, so a small JS height-equalizer (equalizeCardHeights() in vB.js) measures the tallest card and absolute-positions every button at a shared bottom offset. Re-verified by injecting the fixed code onto the live control page: all 3 buttons now land at the identical top:1104 / bottom:1158 in both Chrome and Safari Desktop.

In the Figma design, the "AFP Power Hour" and "Earn the CTP® or FPAC®" card buttons sit at almost the same height (within ~6px of each other), with only the "AFP Events" card sitting noticeably higher (shorter copy). On the live variation, measured directly from the rendered page (Chrome Desktop, 1280×800), the three buttons form a full staircase:

CardButtonFigma bottom offset (relative)Live bottom offset (relative)
1 — AFP Power HourREGISTER FOR POWER HOUR≈232px≈460px
2 — Earn the CTP®/FPAC®EXPLORE CERTIFICATIONS≈238px≈377px
3 — AFP EventsEXPLORE AFP EVENTS≈195px≈333px

Figma intent: Card 1 ≈ Card 2 (level), Card 3 higher. Live result: Card 1 is lowest, Card 2 middle, Card 3 highest — a full progressive staircase, and Card 1 sits ~83px below Card 2 instead of level with it.

Likely root cause: Card 1's button label "REGISTER FOR POWER HOUR" wraps to two lines (vs. one line for the other two buttons), and the card layout doesn't bottom-anchor the button within a shared card height — so the two-line button pushes the whole card's visual weight down instead of just the button growing in place. Confirmed present in both Chrome and Safari Desktop (WebKit renders the same layout, same stagger).

Scope: Desktop/tablet only — the three cards stack full-width vertically on mobile (Pixel 5 and iPhone 12 both confirmed), so this specific misalignment does not reproduce on mobile.

BUG-02 [RETRACTED — false positive, not a real bug] — "Explore Certifications" button href

Originally reported as a malformed placeholder URL. On re-reading the actual source, the code correctly sets href="#TODO-CERTIFICATIONS-URL" — exactly the kind of clean placeholder the client asked for (4:04: "maybe put in a placeholder URL just for now"). The original finding came from reading the browser's resolved .href DOM property in the QA test script (which auto-expands a relative/fragment href to an absolute URL using the current page's address, including its query string) instead of the raw getAttribute('href') value. No code change was needed or made. The other two card buttons ("Register For Power Hour" → same URL as control, "Explore AFP Events" → same URL as control) are confirmed correctly pointing to the same destinations as control, per spec.

BUG-03 [Medium] — Certification tab copy size trends smaller than control, not bigger as requested — FIXED & VERIFIED

The client said (2:44): "If you can bump up the copy size a little bit more, or even maybe we even wrapped two lines if needed, that would be great." Measured computed styles (Chrome Desktop):

ControlVariation
Inactive tabs (CTP / FPAC / Scholarship)20px / weight 800 / line-height 35px16px / weight 800 / line-height 28px
Active tab ("Maintain(ing) Your Credential")14px / weight 400 / line-height 24.5px16px / weight 800 / line-height 28px

The active tab did get bigger (14px→16px, as asked), but the three inactive tabs — the visually dominant reference point in control at 20px — actually shrank to 16px in the variation. Net effect: all four tabs converged to a uniform 16px, which reads as smaller than control's most prominent tab size, opposite of the explicit request to bump the copy up.

Fix applied: .tab-section__nav-btn font-size raised from 16px to 20px (matching/exceeding control's own baseline), padding reduced slightly (44px→28px horizontal) to keep the row fitting comfortably at the larger size. Re-verified live: measured 20px on the injected fixed code.

BUG-04 [Medium] — Eyebrow font doesn't match across the section, despite explicit "should all be the same" instruction — FIXED & VERIFIED

The client was explicit and repeated this twice: eyebrows on the section-2 heading and the "Maintain Your Credential" panel should have "the same font characteristics as [the card-row eyebrows]... the font style, like the weight, the size, the line height, everything else is really consistent, so that's all the same as one another." Measured:

EyebrowFont-size / weight / line-height
Card-row eyebrows (all 3 — reference pattern)15px / 800 / 26.25px
"AFP CERTIFICATIONS" (section-2 eyebrow)16px / 700 / 28px — mismatched
"ALREADY CERTIFIED" (panel eyebrow)16px / 400 / 28px — mismatched, and much lighter weight

Correction: the panel-eyebrow number above (16px/400) was later found to be a measurement artifact — the QA script's text-matching grabbed an unrelated page element (likely a breadcrumb) with coincidentally the same text, not the actual injected eyebrow. The real pre-fix CSS was 14px/700/24px — close to the 15px/800/26.25px target, but not exact.

Fix applied: both .tab-section__title.variation-eyebrow-cert (section-2 eyebrow) and .variation-eyebrow-already-certified (panel eyebrow) set to exactly 15px / weight 800 / line-height 26.25px, matching the card-row eyebrows precisely. Re-verified live: all three eyebrows (card, section-2, panel) now measure identically.

Confirmed Matches (no action needed)

Hero "JOIN AFP" button width

Client asked (0:59): "the join AFP button is wider, it's about as wide as all of these buttons in the box underneath." Measured: hero button = 280px wide; card-row buttons = 209–261px wide. The hero button is in the same range as (slightly wider than) the card buttons — matches intent, a clear improvement over control's cramped 108px-wide button. If the client meant "as wide as the combined row of 3 buttons" rather than "as wide as one button," that would be a much larger width (~1200px) — worth a quick confirmation given the phrasing is genuinely ambiguous, but the more natural reading is already satisfied.

Tab default/position (confirmed against transcript)

Client explicitly confirmed (2:54–3:08): "we're going to move it to position three, but we're still going to default to it." Live build matches exactly — "Maintain Your Credential" is 3rd in the tab order and remains the active/default tab on page load.

Section-2 heading size vs. card headings (confirmed against transcript)

Client self-corrected mid-video (3:28): "this headline here might actually be a bit bigger than these ones, because it is the main headline for section 2." Measured: card headings = 40px, section-2 heading ("Stand Out with the CTP® or FPAC®") = 48px. Matches the corrected instruction.

Font-family parity

Per the client's standing rule ("if it's the same on the wireframe, it should be the same in the page"), computed font-family for the H1 is GothamNarrowBold, Arial, Helvetica, sans — identical string in both control and variation. No font substitution introduced by the variation.

Hero copy, CTA, and layout

Headline ("Advance Your Career with AFP Membership"), subcopy, and single "JOIN AFP" button all match the Figma design exactly, in both Chrome and Safari, desktop and mobile. The smaller hero font size in the variation (48px vs. control's 72px) matches Figma's proportions — verified by direct pixel comparison against the reference image; not a bug.

3-card row content pivot

Card 2 correctly swaps from the control's "Stablecoins & On-Chain Liquidity Certificate" promo to the variation's "Earn the CTP® or FPAC®" copy, with the ® symbols intact everywhere they appear (hero card, section heading, tab label).

"Stand Out with the CTP® or FPAC®" section

New eyebrow, heading, pill-style tabs (vs. control's underline tabs), and the tab reorder (Maintain Your Credential moved from 1st/active to 3rd position while remaining the active/default tab) are all implemented correctly and match Figma. "ALREADY CERTIFIED" tag and "Explore Recertification →" exit link are present; webinar list content is unchanged and correct.

Header/nav

The Figma comparison image shows a visibly larger logo/nav in the variation panel than the control panel — this raised a flag in the spec doc (worth confirming as a Figma export artifact vs. a real change). Resolved by live testing: the live header renders identically sized in both control and variation, across all 4 browser/device combinations. Confirmed as a Figma export-zoom artifact, not a code discrepancy — no action needed.

  • How far down the page does this redesign extend? Anything the client said verbally that isn't visible in the Figma image itself (rationale, additional requirements, corrections) could not be captured.
