Test 12 page speed check: control vs variation

Tested 29 Oct 2026 Lighthouse 12.8.2, Chrome headless Homepage (exp 100052748) and PPC page /medical-malpractice-lawyers/ (exp 100052508)

Verdict: no measurable slowdown, one fixable cost

The Client Stories section does not change the metrics Google uses to judge landing page speed. Largest Contentful Paint, layout shift and first paint stayed within normal run-to-run noise on both pages. The section is added below the fold and the videos don't download until a visitor presses play.

The one real cost is page weight. Each variation page loads 3 poster images that add about 1.1 MB. They're oversized PNGs. Converting them to compressed WebP or JPEG and lazy-loading them would cut that to roughly 150 KB, loaded only when someone scrolls to the section. We recommend making this change before launch so the test carries no speed risk on slow mobile connections.

  • Export the posters as WebP (or JPEG at about 80% quality) at about 830 px wide. That's twice the 415 px card width, so they stay sharp on retina screens.
  • Add loading="lazy", decoding="async", width="830" and height="434" to the <img class="buckfire-12-thumb-img"> tag in the variation code.
  • The poster files on v2.crocdn.com come back without a Cache-Control header. Setting one, or hosting the posters on the site's own media library, lets returning visitors reuse them.

With these changes the variation's added weight drops from about 1.1 MB to about 150 KB, and none of it loads until the visitor scrolls toward the section.

The page's baseline speed is the bigger quality-score risk

Both arms score only 30–50 on mobile, with 2.5–19 seconds of main-thread blocking. That comes from scripts present on every version of the page, not from Test 12: the live chat widget (about 1 MB), reCAPTCHA loaded 3–6 times, Cloudflare Turnstile and Google Tag Manager. If quality score is a concern, deferring the chat widget and loading reCAPTCHA once, only on form interaction, would make a far bigger difference than anything in this test.

How this was tested

  • Lighthouse 12.8.2, performance category only, on headless Chrome with a fresh profile for every run. Mobile uses Lighthouse's default throttling (slow 4G, 4× CPU slowdown); desktop uses its desktop preset.
  • Control and variation runs were alternated so changing network conditions affected both equally.
  • Other tests on these pages were kept the same in both arms. The Test 20 winner (deploy 100052957) is live for everyone. The cre-t-27 trust bar test (100053023) randomly assigns visitors, so it was forced to one arm in both URLs for the run-to-run comparisons.
  • Lab tests from a single machine. Google Ads uses real-visitor field data, which will vary by visitor device and connection.
