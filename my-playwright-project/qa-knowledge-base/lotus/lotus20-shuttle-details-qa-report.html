Bugs

BUG-01 · Low V2's text-only shuttle line still shows a pointer (hand) cursor

V2 is meant to be plain text, but v2.css line 10 keeps cursor: pointer on .cre-t-20-Shuttle-details. Hovering it shows a hand cursor as if it were a link, and clicking does nothing. This fails on Chrome, Safari and Pixel 5 (computed cursor: pointer, text-decoration: none).

Fix: delete cursor: pointer; from v2.css, or set it to cursor: default.

Risk to flag to the developer

Risk · Medium The other live test, LOTUS-16 (exp 100052833), copies the cards, and Test 20 depends on running before it

The QA links also put the visitor into Convert exp 100052833 (cre-t-lotus-16, the "Recommended" feed). On first load it hides all 30 real cards ([id^="car-"]) and shows copies in <cre-t-lotus-16-card> elements, built from card.innerHTML about 400ms after the cards exist. Test 20 only adds its shuttle line to the real cards ([data-slice-type="fleet_category"] [id*="car"]>div:nth-child(3)). The copies don't have an id, so Test 20's selector never matches them.

  • In our first check the copies did carry the shuttle line (30 of 30 visible), because Test 20 ran before LOTUS-16 made its copies. The page then had 60 shuttle lines: 30 hidden on the real cards and 30 visible on the copies.
  • This only works because of timing. If LOTUS-16 copies a card before Test 20 adds its line (slow device, slow network, or a rebuild after a currency or date change), that visible card will have no shuttle line, and in V1 there's nothing to click. LOTUS-16 rebuilds on currency change (+500ms and +1500ms), on date "Update", and on filter changes.
  • In the automated runs, clicking "Update" to close the date panel put LOTUS-16 into its normal list (no copies), so the automated checks covered the site's own cards. The copied-card case was only checked once by hand.

Suggestion: widen Test 20's selector to cover the copies as well, for example [data-slice-type="fleet_category"] [id*="car"]>div:nth-child(3), cre-t-lotus-16-card>div:nth-child(3). The existing "already has a line" check prevents duplicates. Also confirm with the client whether LOTUS-16 will still be live when Test 20 launches.

Notes (not failures; please confirm with the client)

  • No backdrop behind the modal. The overlay <div class="cre-t-20-overlay"> is commented out in vB.js, so the listing behind the modal isn't dimmed (see screenshots). Check this against the wireframe.
  • Escape doesn't close the modal. This is the same in all 3 browsers.
  • The page behind still scrolls while the modal is open. Scrolling moved the page about 600px (e.g. 703 → 1303) with the modal still open. Because the modal is position: fixed it stays on screen, but the page moves behind it.
  • Accessibility. The V1 "link" and the "OK, Got It" button are plain <div>s with no role or tabindex, so keyboard users can't reach them. Also, aria-labelledby="cre-t-20-modal-title" points to an id that doesn't exist (the <h2> has no id).
  • Mobile title size. The 36px title wraps onto 2 lines on a 393px-wide phone. The modal still fits (353×464 on Pixel 5) with no scrolling inside it. Check this against the wireframe.
  • Switching to German from inside the site. Switching EN → Deutsch from the menu leaves 30 hidden English shuttle elements in the page code, because the page-watcher keeps running. They're not visible, since the CSS only applies to en-us, and loading the German page directly adds nothing. No action needed for users.

Behaviour that is the same in control: visitors with no dates get the "Rental time" panel opened on page load (on desktop a panel over the page, on mobile the full-screen "Iceland Awaits." sheet). Only "Update" / "Check the fleet" closes it. The tests close it that way, like a real visitor.
