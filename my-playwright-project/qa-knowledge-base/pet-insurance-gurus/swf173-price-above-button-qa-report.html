SWF173 — Price Above Button (Desktop)

On a fresh All Pets load the variation matches the wireframe. Every listing gets an "Average Plan Cost" price above VIEW PLANS, the figure matches the card, and the right column is centred to the pixel at 1024–1920px on all six URLs. The problem is that the price is written once and never updated. Clicking Cats or Dogs, entering a ZIP, or clicking Show More after the first ~17 seconds leaves cards with a wrong or missing price, and after a ZIP some cards show another insurer's price. These are the site's main interactions, so the price is wrong for many real visitors.

Bugs

highBUG-01

Duplicated price does not follow the Cats / Dogs tabs

All targeted URLs · Chrome + Safari · also visible in the client's own screen recording

The site changes every listing's Average Plan Cost when a pet-type tab is clicked. The new price above the button keeps the All Pets figure, so the two prices in the same card disagree.

On Dogs the duplicated figure is sometimes the pre-discount price hidden by CRE-T-143 ($23.44 is Lemonade's original All Pets price), and sometimes the stale All Pets price ($20.28). Both are wrong. Returning to All Pets lines the prices up again.

Cause: addPriceToCard() exits when a card already has .SWF173-price, so a card is priced once and never refreshed. When the React list re-renders a card while the observer is still running, the price is re-read from .plan-detail-content textContent, which still includes CRE-T-143's hidden original span, and the regex takes that first, hidden number.

highBUG-02

After a ZIP is entered, cards show stale prices, some belonging to another insurer

mediumBUG-03

Show More cards get no price if clicked about 17s or more after load

All URLs with Show More · Chrome + Safari

The observer starts 2s after the code runs and disconnects 15s later. Cards 8–10 (Liberty Mutual, Odie, AKC) only mount when Show More is clicked, so a late click reveals cards with no price above the button. A click within the window works (passed in both browsers).

Fix: keep a lightweight observer on the listing container for the life of the page (or re-run on Show More / tab / filter clicks), and re-sync every card's price instead of skipping cards that already have one.

mediumBUG-04

Best Overall card has no price on /comparison/ and /canada/

/comparison/ (Pets Best, $28.79/mo) · /canada/ (Fetch, $85.89/mo) · Chrome + Safari

On these two pages the Best Overall card sits in .best-overall-container, outside .plan-repeater, so CTA_SELECTOR never matches it. On /, /home/, /compare/ and /cat-insurance/ the Best Overall card does get the price, so the treatment is inconsistent between pages. The brief says "each listing's button". Drop the .plan-repeater prefix from the selector, or confirm with the client that Best Overall is out of scope.

lowBUG-05

Race with CRE-T-143 can show the pre-discount price on first paint

/?petType=cat · Chrome · intermittent (1 of 2 loads)

On one direct landing the duplicated prices were the CRE-T-143 originals ($16.94, $18.44, $20.63…) while the left column showed the discounted figures ($14.65, $15.95, $17.84…). A second load was correct. When SWF173 runs before CRE-T-143 has added .cre-t-143-discounted-price, the fallback reads the original price, and BUG-01's "price once, never refresh" logic means it is never corrected. Reading only visible child spans (see the PIG client notes on CRE-T-116/143) and re-syncing on mutation fixes this along with BUG-01.

lowBUG-06

"/mo" is the same size as the amount; wireframe shows a larger amount and a smaller "/mo"

Design · all pages · Chrome + Safari

Live: amount 18px / 700 and .SWF173-mo 18px / 700 (no rule for it in vB.css). In the wireframe the dollar figure is noticeably larger than the left-column price and "/mo" is set smaller and lighter. Label (12px, #8C8EA0, uppercase, Montserrat 500) matches the wireframe.

Coverage gaps

  • Safari run incomplete. The system stopped the WebKit run for low memory after 26 of 27 tests, before results were saved. The Safari screenshots confirm BUG-01, BUG-02, BUG-03 and BUG-04. Eight Safari tests hit the 60s page-load limit (/, /compare/ control, 1024px, 1920px, re-run, Cats, ?petType=cat, round-trip), so they are inconclusive, not failures. The Safari mobile-audience check did not run.
  • Video has no audio track. All 47 seconds were reviewed frame by frame. It shows BUG-01 on the Cats and Dogs tabs.
  • Headless WebKit renders all text, the site's own included, in a lighter weight. This is an environment effect, not a variation defect.
  • Edge and Firefox were not requested and not run.

Suggested fix (one change covers BUG-01, 02, 03, 05)

Replace "insert once, skip if present" with a sync: on every mutation of the listing container (keep the observer alive; it is cheap when debounced), for each .plan-box read the visible left price (.cre-t-143-discounted-price, otherwise only child spans whose computed display is not none), then create or update that card's .SWF173-amount. Drop the .plan-repeater prefix from the selector for BUG-04. Add .SWF173-mo{font-size:…;font-weight:500} and raise the amount size for BUG-06.
